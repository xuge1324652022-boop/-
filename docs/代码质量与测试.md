# 代码质量与测试

项目支持 Node.js 22.16 及以上的 22.x，以及 24.x。`package.json` 的 `engines`、GitHub Actions 的两档测试环境和 Cloudflare 构建使用的 Node 22.16 相容。Vite 8 的最低要求是 Node 20.19 / 22.12，项目范围进一步限制为实际验证的版本系列。[Vite 8 官方说明](https://v8.vite.dev/blog/announcing-vite8#node-js-support)

## 本地检查

先运行 `npm ci`，再按需要执行。公开交付还必须运行 `npm run check:privacy`，拒绝私人字段与未审核二进制：

| 命令                      | 检查内容                                                                         |
| ------------------------- | -------------------------------------------------------------------------------- |
| `npm run lint`            | ESLint 10、TypeScript 和 Vue 3 的正确性规则，警告也使检查失败                    |
| `npm run typecheck`       | `vue-tsc` 检查源码和 Vue 模板的类型                                              |
| `npm run test:unit`       | Node 内置测试运行器验证滚轮、导航中断恢复、语言持久化、路由元信息和响应式图片    |
| `npm run test:deployment` | 运行导航、触摸守卫、微信媒体、移动作品、关于页、Range 和部署协议的本地 mock 回归 |
| `npm run check:motion`    | 校验中文动效组件库与当前原始源码、导入和 JSON 解析是否一致                       |
| `npm run check:images`    | 从交付图片读取实际像素宽度，校验响应式图片清单是否需要重新生成                   |
| `npm run build`           | 生产构建                                                                         |
| `npm run format:check`    | 按统一 Prettier 配置检查维护中的源码和脚本格式，不写文件                         |
| `npm run format`          | 按相同配置写入格式；执行前应检查改动范围                                         |

`test:unit` 使用 `--experimental-strip-types`，以便 Node 22.16 与 Node 24 都能直接读取只有可擦除类型的 TypeScript 函数。这只移除类型，并不替代 `typecheck`。[Node 官方说明](https://nodejs.org/learn/typescript/run-natively)

现有 `test:deployment` 的 7 个脚本无需启动开发服务器，也无需 Edge、Chrome 或 Playwright。它们使用真实源码加 VM、DOM/媒体替身和 ASSETS/fetch mock；Range 验证已经覆盖 206、416、If-Range、HEAD、PDF、逐块读取与取消。它们验证逻辑约束，真实浏览器的布局、媒体兼容性与视觉体验仍应按交付流程另行验收。这里没有把已有断言重复套一层单测。

## 自动检查

`.github/workflows/代码质量检查.yml` 在 main 分支 push、所有 pull request 和手动触发时运行，在 Node 22.16.0 与 24 两档环境依次执行：

1. 使用锁文件安装依赖，禁用依赖生命周期脚本。
2. `lint` 和 `typecheck`。
3. `test:unit` 与 `test:deployment`。
4. `check:motion`、`check:images` 和生产 `build`。
5. 读取构建产物，验证静态路由页面的 head 与 404 交付。

工作流只需要仓库读取权限，不读取部署凭据、不部署网站、不发布 npm 包。要禁止合并未通过检查的 PR，应在 GitHub 分支保护或规则集中把这两个 `quality (Node …)` 检查设为必过检查；工作流文件本身不会修改仓库规则。

## 格式与检查范围

ESLint 使用 flat config，仅为 `src/`、维护中的 `scripts/*.mjs`、`deploy/*.mjs`、`tests/` 和根配置文件启用适当的浏览器或 Node 环境。Vue 使用 essential 正确性规则，TypeScript 使用 recommended 规则；格式交给 Prettier。Cloudflare 的 `FixedLengthStream` 是部署环境全局，显式声明为只读。以 `_` 开头的接口占位参数，以及现有 `Preloader` 名称，是精确记录的兼容约定。

ESLint 和 Prettier 都排除 `tmp/`、`outputs/`、`backups/`、生成的 `动效组件库/`、作品、参考资料、交付副本和依赖目录。`.editorconfig` 定义 UTF-8、LF、两空格缩进及末尾换行，Python 使用四空格。

本次接入不批量改写既有文件格式。历史源码尚未全部符合 Prettier，因此 `format:check` 可用于查看和逐步收敛格式差异，目前不作为 CI 必过项；CI 中的 lint 始终执行有效的正确性检查。新增代码应按统一配置格式化，避免把大面积格式变化混入功能修改。[Prettier 官方说明](https://prettier.io/docs/install)
