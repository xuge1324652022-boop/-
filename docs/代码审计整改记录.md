- 配置支持更换 `deploy/site-config.json` 中的站点根网址，构建时可通过 `SITE_ORIGIN` 覆盖。切换域名后仍需正常配置域名绑定及重新部署。

这些是资源交付和代码证据，不代表已测得特定设备的 LCP、帧率或网络耗时。

## 质量检查与结构

- 增加 ESLint、Prettier、EditorConfig 和 Node engines。GitHub Actions 在 Node 22.16 与 24 两档执行 lint、typecheck、单元测试、部署 mock、中文库校验、图片校验、生产构建和路由产物校验。格式配置已接入，历史源码不做整库格式改写，format:check 暂不作为必过项。
- 入口从 `main.js` 改为 `main.ts`，删除 tsconfig 中不存在的配置文件引用。
- 导航时序迁到 `useRouteCurtainNavigation()`，版本所有权与导航失败分类有独立函数。测试直接执行实际 TypeScript，覆盖导航竞态、重复导航、超时、迟到错误、重试、语言存储和动态偏好变化。
- CardVisual 的五类作品模板与样式拆成五个子组件；编译模板 AST 与原版展开比较一致，父子共 133 条 CSS 的选择器和声明一致。ThreeHome 的姿态写入和样式缓存移到 `galleryRenderer.ts`；ColorView 的静态文案、片单与颜色移到 `colorPage.ts`。这些页面仍有较长的布局和生命周期代码，后续可按实际维护需求继续分解。
- 语言选择保存到 localStorage，初始化和切换都同步 html lang；存储不可用时保持页面可用。减少动态偏好变化可以结算正在等待的转场；删除永远不会匹配的 card 路由条件。
- dev 默认仅监听 127.0.0.1、不自动打开浏览器；忽略作品、临时与交付目录的文件监控。

原审计中的两项经核验有差异：现有七个 test:deployment 脚本使用 Node VM、DOM/媒体替身及 ASSETS/fetch mock，无需本机浏览器和开发服务器；Cloudflare 构建此前已经包含 typecheck、build 和部署验收，本次补上独立 GitHub 质量工作流并强化部署前检查。原 App 中的 script setup 状态属于组件实例，本次抽取的目的在于明确接口和便于测试。

工作流成功不等于分支保护已启用。仓库规则若要求禁止合并失败检查，应另把两档 quality 检查设为 required checks。
