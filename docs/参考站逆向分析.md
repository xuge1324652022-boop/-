## Color：最需要对齐的是动作顺序

目标组件是 `ColorExplorePosters`，它位于颜色探索后半段。第一张是由背景、HTML 大标题、小字和图框组成的海报；之前探索场景中的图像通过 GSAP Flip 衔接到右下图框。它并非把四张现成图片同时摆成倾斜构图

```mermaid
flowchart LR
  A[整屏背景与图像] --> B[背景裁剪成首张海报\n图框与文字衔接]
  B --> C[第二张从下方进入]
  C --> D[第三张从下方进入]
  D --> E[三平面进入空间视角]
  E --> F[正常滚动离场\n衔接下一段文字]
```

以下是发布代码的时间线坐标。`scrub:true` 将时间线映射到滚动距离，因此它们不是用户滚动时的固定秒数

| 轨道 | 起止坐标 | 曲线 / 行为 |
| --- | --- | --- |
| 图像框衔接 | 0–1.2 | `Flip.fit`、`power3.out` |
| 全屏背景裁成首张 | 0.1–1.1 | 实测四边 inset、`power3.out` |
| 标题与小字 | 0.2–1.2 | x 从 -20% / +20% 回零、淡入、`power3.inOut` |
| 第二张 | 1–2 | `y:100lvh → 0`、`power2.out` |
| 第三张 | 1.5–2.5 | 同上、间隔 0.5 |
| 三平面转向 | 2.1–3.1 | `rotateY:0 → -65°`、`power1.out` |

转向与最后一张入场末尾有 0.4 坐标单位的少量重叠；原站不是严格串行，也不是从开头全部并发。每个平面设置自己的 `transformPerspective:2000`，不能再断言原站一定用了共同父级相机

布局事实：主海报宽 `52rem`、比例 `555/705`，1440px 桌面约 520×661px；附属海报宽为主张的 85%。目标 root 高 `350lvh`，主海报时序区域高 `200lvh`；ScrollTrigger 为 `top bottom` 到 `bottom top-=75%`

**现场核对**：固定 1440×900、关闭减少动态设置，用 PageDown 分段采样。整屏阶段、裁剪中、首张完成、附属卡片出现、透视阶段与随后正文均可在保存的截图与 DOM 中对应。采样是离散键盘滚动，不等于真实滚轮/触控板逐帧性能测试

Evidence：`ev_7414c24e17ef0d9e9dabe5a290f61931ccca260406189d175908cd77d36b52a3`，步骤 `rest-14` 至 `rest-18`

## Motion：堆叠、收拢与内容动态是不同机制

初始卡片约 -14.4° 的 rotateX、scale 0.6，z 从 -900px 分层。收拢时 z、倾角归零，scale 到 1。容器为真正的 1200px 透视空间，桌面 sticky 段高 4 个视口

滚动进度大于 0.7 时进入交互模式，点击才使 selected index 循环到下一张。没有发现“滚一下就递增一张”或“等待所有视频播完才释放页面”的逻辑；释放位置由 sticky 滚动距离决定

现场 `rest-2`、`rest-3`、`rest-4` 中第一张始终具有 selected class，但后来由 trimmed 视频切到 full 视频，因此画面变化不能直接解释成换卡。full 媒体本身是循环 MP4；参考站卡片内持续活动的文字与图像很大一部分来自预制视频

来源：[MotionIntro](https://brand.squarespace.com/_nuxt/lGJEKPwO.js)、[StickyBlock](https://brand.squarespace.com/_nuxt/LHB4rC_J.js)

Evidence：`ev_e8f7f49935fb1684de0ab8d74eca7085cb10756e44f6f35fb3d34d3582191253`

**我们的适配**：保留用户要求的完整海报与逐页观看顺序，卡内文字/块面使用自己的 DOM 动效。这属于针对作品的设计，并不是从原站提取到了对应海报字块的动画参数

## 文字、滚动、索引、鼠标

| 对象 | 原站发布代码事实 | 对项目的含义 |
| --- | --- | --- |
| 平滑滚动 | Lenis 1.3.14，实际实例 `duration:1.2`；GSAP ticker 驱动、ScrollTrigger 同步更新 | 只保留一个主要滚动平滑来源，避免 native / 105ms / 300ms 在交接处手感突变 |
| 普通正文 | IntersectionObserver threshold 0.5；整体 y:5rem，视觉行 y:6rem + opacity；行 0.8、`power3.out`、stagger 0.08；一次入场 | 普通段落不要一律套标题硬遮罩，不应上滑下滑反复重播 |
| 标题、菜单 | 行 mask，y:100%→0，0.8、`power3.out` | 保留视觉行分组与窗口裁剪 |
| 索引入口 | 桌面固定透明区域；下滑隐藏、上滑显示；出现0.5 `power3.out`，隐藏0.2 `power1.in` | 真实原站没有观察到1.6秒idle计时器 |
| 索引面板 | blur40px、背景opacity0.8；打开0.6 `power2.out` / 关闭0.4 `power2.in`；行间隔0.04；hover横移4rem、非活动opacity0.3 | 当前clip揭幕并非同一套菜单效果，可以按实际面板机制校准 |
| 鼠标 | 交互区域内实心点 + Next / Explore / HEX；点0.8rem、文字1.6rem、间距0.8rem；lambda26阻尼；普通区域保留原生指针 | 当前纯原生鼠标缺少局部动作反馈；不要做全站圆环 |

## 字体与网格

原站英文主字体为 Clarkson，默认400；这不是项目现有字体的授权来源。本项目应继续使用已有可用字体，按字面大小和字宽调整中英比例

1440px 桌面中 `1rem≈10px`：12栏、栏距20px、侧边40px、容器最大1360px；H1约200px / 行高0.8，intro正文约48px / 行高1，普通大正文约32px / 行高1.1，字距约-0.03em。原站基础色包括 #000、#111、#fff、#f6f6f6、#e1e1e1，组件可覆盖背景色。我们的暖纸背景属于用户既定视觉方向，不需要为了复刻擅自换成白色

来源：[全局样式](https://brand.squarespace.com/_nuxt/entry.CdBDcUZV.css)

## 目前代码的具体差距与实施顺序

源码审查详情保存在 `outputs/reference-analysis/2026-10-14/local-audit.md`

1. `InternshipDepthComposition.vue` 第四张入场 .92–1.38、转向1.20–1.80、整体离场1.30–1.90，大量重叠且没有最终阅读段。先重新划分收拢、逐张进入、转向、定格阅读、释放滚动的边界，再校准曲线
2. 同组件当前 perspective 为主卡宽×4.3、rotateY -54°。原站实际为2000px / -65°且有明确层级位置。先保持主张、附属张85%比例，按我们四份素材追加第三张附属卡，而非让四张同时散开
3. 原站转向后的整体离开主要跟随长文档/sticky释放，我们的额外组位移过早。验收要记录退出时 card 与正文的轨迹，禁止正文再次反向追赶
4. `ReferenceIntroduction` 现有 hasPlayed 和视觉行分割是正确方向；区分标题mask与普通正文，不恢复回滚重播。字体重排时立即完成旧动画的边缘情况需单独复现后再改
5. 滚动控制先统一来源，再处理索引/查看器内部滚动的放行，避免全局 preventDefault 吃掉局部滚轮
6. 索引样式和局部动作光标最后接入；已有右上入口与用户idle规则保留

建议的四张作品节奏保存在 `outputs/reference-analysis/2026-10-14/reference-tokens.json`，其中 `proposal` 明确是我们的适配，不冒充原站参数
